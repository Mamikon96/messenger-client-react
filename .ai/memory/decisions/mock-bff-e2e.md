# Решения: mock-BFF и e2e

Формат записи и правила — `../decisions.md`. Записи до FE-D51 перенесены из исходного `decisions.md` без изменений.

## FE-D13 — e2e: mock-BFF только для auth и навигаций, REST и WebSocket — через Playwright (2026-10-09)
- **Решение:** локальный mock-BFF (FE-D04(6)) остаётся только для auth и полных навигаций (OAuth-редиректы, cookie, 401). REST и WebSocket в e2e мокаются средствами Playwright: `page.route` и `page.routeWebSocket` (Playwright ^1.63, новых зависимостей нет). Фикстуры — строго по разделу 4 «Модели данных» `docs/client-integration.md`.
- **Почему:** выбор пользователя; не нужен пакет `ws`, моки REST/WS описываются в самом тесте рядом со сценарием, формат данных привязан к контракту бэкенда.
- **Альтернативы:** расширить mock-BFF до REST и WS (нужен пакет `ws`, риск расхождения мока с сервером); e2e на реальном бэкенде (нет тестового входа, OAuth не проверен — 8б.10 документа).

## FE-D40 — Ошибки валидации тела запроса в mock-BFF там, где спека молчит (2026-10-14)
- **Решение (выбор пользователя):** для `POST /api/auth/register` и `POST /api/auth/login` (бывшая спека `auth-password-spec.md`, удалена в FE-98, этого не описывала; в `docs/client-integration.md` §1.3 — «Коды details» — описано): (а) поле неверного типа (число, массив и т. п.) — `400 validation_failed`, `details: [{field, code: "required"}]`; (б) битый JSON или тело не объекта — `400 validation_failed` без `details`, пустое тело считается `{}`; (в) одно поле с несколькими нарушениями — один код на поле, приоритет `required` > `too_long` > `invalid_format` (для пароля порядок `required` > `too_short` > `too_long` > `too_common` не выбор, а следствие: `too_short` и `too_long` взаимоисключающие, `too_common` проверяется только для 12..256 байт). Пункт «тело не объекта = битый JSON» подтверждён пользователем отдельно. Покрыто контрактными тестами `e2e/mock-bff.contract.spec.js`.
- **Почему:** клиент реагирует на `details`, а не на `message` (FE-D38); один код на поле даёт форме одно сообщение. Расхождение с реальным бэкендом — вопрос к бэкенду при синхронизации спеки.
- **Альтернативы (не выбраны):** отдельный код `invalid_type`; `details` и для битого JSON; перечисление всех нарушений поля списком.
