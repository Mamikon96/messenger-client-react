# Протокол памяти
Читать: перед началом работы над задачей разработки (шаг «Старт») и перед ответом пользователю после любых изменений (шаг «После правок»).
Источник: FE-D27, FE-D41, FE-D55; исполняют `scripts/check-memory.sh` и hook `Stop`. Пересмотреть, когда меняется формат памяти или hooks.
Описание файлов памяти и их форматов — `.ai/memory/README.md`.

## Старт (читать минимум)
- Первым шагом — `bash scripts/git-task.sh start …`: проверка состояния (репозиторий, задача в `tasks.md`, чистота дерева, актуальность базы, `check-memory.sh`), затем переключение на ветку задачи (`.ai/rules/git-flow.md`, «Автоматический цикл»).
- Сводку («В работе», последняя приёмка, фокус) в начале сессии печатает hook `SessionStart` (`scripts/session-brief.sh`); если она в контексте — для продолжения задачи `tasks.md` целиком не перечитывать. Целиком `.ai/memory/tasks.md` — когда берёшь задачу из бэклога или заводишь новую; `.ai/memory/queue.md` при этом не читается (только при пополнении, когда в «Бэклоге» меньше 3 задач). Задача из бэклога → сразу в «В работе» с контрактом (`.ai/rules/task-contract.md`, проверяет `scripts/check-contract.sh`); тесты и код — только после согласования открытых вопросов. Задачу из `queue.md` по просьбе пользователя переносят сразу в «В работе» (с контрактом), минуя «Бэклог»: `git-task.sh` берёт только задачи из `tasks.md`.
- Остальное — только по необходимости (таблица «когда читать» в `.ai/memory/README.md`): `state.md` — баг/регрессия/известные проблемы; `architecture.md` (роутер) — новые модули, правка структуры, затем только нужный файл из `architecture/`; `decisions.md` (роутер) — архитектурный выбор или новая технология: найти строку по теме или ID и открыть только указанный файл из `decisions/`, не читать все.
- Факты из памяти перепроверять по коду: расхождение = память неверна, исправить.
- Независимые команды и чтения — одним вызовом (несколько Read/Grep в одном ответе, команды Bash через `;`, а `&&` — только если следующая зависит от успеха предыдущей), без `cd` в корень проекта: каждый tool-вызов заново читает весь контекст (FE-151).

## После правок (до ответа пользователю)
После ЛЮБЫХ изменений (код, тесты, конфиги):
1. `tasks.md`: промежуточный прогресс → «Осталось»; новая найденная работа → «Бэклог» (в нём ≤7 задач: если есть менее приоритетная, наименее приоритетная (с наибольшим P; при равном — последняя в списке) уходит в конец `.ai/memory/queue.md`, иначе новая дописывается в конец `queue.md` без чтения, FE-D53); правка вне задач → отдельная запись («В работе» или «Сделано»).
2. `state.md` — по сверке с кодом, каждая проблема с путём к файлу; `architecture/*.md` (нужный файл по роутеру `architecture.md`) — если изменилась структура.
3. Штамп `> Проверено: ГГГГ-ММ-ДД @ <sha>[+dirty]` (дата — `date +%F`, sha — `git rev-parse --short HEAD`).
4. `bash scripts/check-memory.sh` (падает, если код изменён позже `tasks.md`). Hook `Stop` (`scripts/hooks/stop-memory-check.sh`) запускает его сам перед концом ответа и возвращает агента к работе при ошибке.
- «Сделано» — архив `.ai/memory/done.md` (роутер-таблица) + `done/<ID>.md` (раздел в `tasks.md` не ведётся; читать только за историей, FE-D52): запись с датой добавляется только при выполнении `acceptance.md` — файл `done/<ID>.md` (заголовок `# <ID>`, затем запись; для записи без ID — `done/<ГГГГ-ММ-ДД>-<слаг>.md`) и строка `| Дата | ID | Суть | Файл |` в конец таблицы роутера; задача удаляется из `tasks.md`. Запись — одна строка `- ГГГГ-ММ-ДД — FE-NN: … · Кейсы: <UC-… из контракта> | нет · …`: поле «Кейсы:» обязательно — по нему `--require-qa` при `git-task.sh commit` восстанавливает объём QA (FE-D35). При ≥2 раундах ревью/QA в записи после вердикта — «(N раунда; причина: <категория>)», категории — `acceptance.md` (FE-145).
- Запись в `decisions/<тема>.md` + строка в роутере `decisions.md` — сразу после выбора пользователя, не раньше (`tech-approval.md`); без выбора не писать.
- Не дублировать в памяти то, что очевидно из кода или git.

## Итог
Финальный отчёт — по шаблону `.ai/rules/report-format.md`, строится из обновлённых файлов памяти.

## Сессия и контекст (FE-D41)
- Одна задача — одна сессия; между задачами `/clear`. Контекст сессии дорожает с каждым ходом, поэтому порог абсолютный и зависит от модели основной сессии: Sonnet/Haiku — 90K, Opus и прочие — 150K токенов (не доля окна). Hook `Stop` (`scripts/hooks/context-guard.sh`) возвращает агента при достижении порога: сохранить «Осталось» в `tasks.md`, штамп, `check-memory.sh` = 0 и закрыть сессию. В субагентах тот же порог проверяет hook `PostToolUse` (по `agent_id`): после инструмента агент получает указание сохранить состояние и завершиться отчётом «сделано / осталось».
- Модель основной сессии (FE-D55): по умолчанию Sonnet; Opus — для архитектурных, исследовательских задач и задач анализа и планирования (на них агент в начале предлагает пользователю переключиться). Пороги выше подтверждены замером и не меняются.
- Код задачи пишет `react-engineer`; основная сессия ведёт контракт, гейты и git. Исключение (FE-D57): правки до 3 файлов в `scripts/` и `.ai/` без `src/` и `mock-bff/` основная сессия делает сама, без `react-engineer`; гейты те же.
- Бэклог — индекс: ≤7 строк в `tasks.md` (остальное — `.ai/memory/queue.md`, пополнение до 7 при <3 задач, FE-D53), строка ≤200 символов, подробности — .ai/memory/backlog/FE-NN.md (открывать, когда задачу берут в работу). Заменённые решения лежат в `.ai/memory/decisions-archive.md` — искать там только историю.
