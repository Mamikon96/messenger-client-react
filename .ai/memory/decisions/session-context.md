## FE-D41 — Экономия токенов: структура памяти и дисциплина сессий (2026-10-15)
- **Решение (выбор пользователя):** (1) бэклог в `tasks.md` — индекс, строка ≤200 символов; подробности задачи — файл .ai/memory/backlog/FE-NN.md, читается только когда задачу берут; (2) решения с пометкой «ЗАМЕНЕНО» — в файл .ai/memory/decisions-archive.md; (3) правила, которые исполняет скрипт (`git-flow.md`, `acceptance.md`), сокращаются до «что запускать и что делать при ошибке»; у файлов правил — источник и условие пересмотра; (4) порог контекста — абсолютный, по модели: Sonnet и Haiku — 90K, Opus и прочие — 150K (уточнение пользователя 2026-10-15), не 50% окна 1M; механически: основная сессия — hook `Stop`, субагенты — hook `PostToolUse` (по `agent_id`, транскрипт `<сессия>/subagents/agent-<agent_id>.jsonl`): после превышения порога агент получает указание сохранить состояние и завершиться; агент с правом записи (`react-engineer`) пишет «Осталось» в `tasks.md`, остальные возвращают сделанное и оставшееся в отчёте, основная сессия передаёт работу новому агенту того же типа. `SubagentStop` отклонён: срабатывает только по завершении агента и не останавливает рост контекста посреди работы (выбор пользователя 2026-10-15); одна задача — одна сессия, `/clear` между задачами; (5) код задачи пишет `react-engineer`, основная сессия — контракт, гейты, git; (6) лёгкий трек: P3 без изменения поведения (`Кейсы: нет`) — `react-reviewer` на sonnet; QA — по общим правилам (FE-D29).
- **Почему:** анализ транскриптов 2026-10-04…13: основная стоимость — повторное чтение большого контекста на каждом ходе (сессия 3367b2fe: 233 хода, средний контекст 283K, 65,6M cache read); порог 50% при окне 1M не срабатывал; бэклог 40K символов читался целиком при каждом взятии задачи.
- **Альтернативы (не выбраны):** только сокращение файлов без порога сессии (эффект — проценты, не разы); порог в процентах окна; QA не запускать для P3 (ослабляет гейт, который исполняет скрипт).

## FE-D49 — Стартовый контекст: функции claude.ai и листинг скиллов (2026-10-17)
- **Решение (выбор пользователя):** уточняет FE-D42. Глобально (`~/.claude/settings.json`, вне репозитория): `enableArtifact: false`, `disableClaudeAiConnectors: true`, `skillListingMaxDescChars: 300`; `skillOverrides`: синхронизированные скиллы claude.ai `anthropic-skills:*` — `off`, кроме `skill-creator`; `claude-in-chrome` — `off`; `dataviz`, `claude-api`, `plugin-authoring`, `schedule`, `loop`, `run`, `keybindings-help`, `artifact-*` — `user-invocable-only` (вызываются через `/name`, модель их не видит). В проекте (`.claude/settings.json`): стековые скиллы `angular-development`, `nestjs-development`, `nextjs-development`, `nodejs-backend`, `sql-development` — `off`. Плагин `chrome-devtools-mcp` остаётся (нужен qa-tester по FE-D43).
- **Почему:** первый ход интерактивной сессии вырос до 46–49K токенов (Claude Code 2.1.300): тул Artifact, коннектор Claude Docs и описания синхронизированных скиллов грузятся всегда, хотя в проекте не нужны. MCP-тулзы уже отложенные (ToolSearch), в контексте только их имена. Замер headless-сессии `claude -p` в проекте: 28 646 → 21 235 токенов первого хода.
- **Ограничение:** `skillOverrides` не действует на скиллы плагинов («A plugin skill is managed with the plugin»): 7 скиллов `chrome-devtools-mcp:*` убираются только отключением плагина.
- **Альтернативы (не выбраны):** отключить плагин `chrome-devtools-mcp` и перевести диагностику qa-tester на Playwright (меняет FE-D43); `disableBundledSkills` (убирает и нужные `/code-review`, `/simplify`); оставить Artifacts.

## FE-D54 — Отключить плагины chrome-devtools-mcp и context7 в проекте (2026-10-18)
- **Решение (выбор пользователя):** частично заменяет FE-D43 (диагностика), уточняет FE-D49. В `.claude/settings.json` проекта `enabledPlugins`: `chrome-devtools-mcp@claude-plugins-official` и `context7@anthropic-plugin-directory` — `false`. `qa-tester` проходит кейсы и снимает диагностику (консоль, сеть) только через Playwright MCP; инструменты Chrome DevTools убраны из его `tools`. Глобальные настройки пользователя не менялись.
- **Почему:** аудит транскриптов 2026-10-09…18 (107 сессий): вызовов обоих плагинов в проекте 0, Playwright — 896. Плагины добавляют около 1,5–2K токенов к каждому ходу и 7 скиллов `chrome-devtools-mcp:*`, которые `skillOverrides` не убирает (FE-D49).
- **Альтернативы (не выбраны):** оставить `chrome-devtools-mcp` для диагностики qa-tester (FE-D43); оставить `context7` для поиска актуальных доков; ничего не отключать.

## FE-D55 — Модель основной сессии и пороги контекста (2026-10-20)
- **Решение (выбор пользователя):** уточняет FE-D41. Основная сессия по умолчанию на Sonnet; Opus — для архитектурных, исследовательских задач и задач анализа и планирования. Пороги контекста не меняются: Sonnet/Haiku 90K, Opus 150K.
- **Почему:** замер транскриптов (аудит токенов 2026-10-20): `context-guard.sh` срабатывает — после введения хука (2026-10-15) Sonnet-сессии заканчиваются на 95–104K (один выброс 129K), Opus на 145–176K; сессии на 265–451K были до хука. Дорогая сессия Opus 12.10 (18% cache read) — до хука.
- **Альтернативы (не выбраны):** порог Sonnet 120K или 70K; Opus для всех P1; модель не фиксировать.
