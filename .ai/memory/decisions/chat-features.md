# Решения: Чаты: поиск, отправка сообщений

Формат записи и правила — `../decisions.md`. Записи до FE-D51 перенесены из исходного `decisions.md` без изменений.

## FE-D45 — Поиск людей, direct-чат из поиска, пустые группы и приглашение (2026-10-17)
- **Решение (выбор пользователя):** (1) поиск людей серверный — `GET /api/users?q=&limit=` (добавляет бэкенд: `q` от 2 символов, без себя, только по `name`, `login` в выдаче нет); клиент — хук `useUserSearch` (debounce + `AbortController`, локальное состояние, не в RTK) и presentational `PeopleSearch` с действием на строке `getAction(user) → {label, icon, disabled, onClick}`. (2) Поиск — в левой панели над списком чатов; действие «Написать <имя>» → `POST /api/chats {type:"direct", userId}`, на 201/200 — upsert чата и открытие; `JoinForm` и `chatCreated` удаляются. (3) Группа создаётся без участников (бэкенд разрешает `memberIds: []` и добавляет удаление группы владельцем); «Новая группа» — кнопка в левой панели, только название. (4) «Пригласить» = сразу добавить (`POST /api/chats/:id/members`), только owner; кнопка в шапке диалога → модалка с тем же `PeopleSearch` (участники — disabled «уже в чате»); после 204 — перечитать `GET /api/chats/:id` до FE-41.
- **Почему:** фильтрация всего `/api/users` на клиенте раскрывает список всех пользователей при открытой регистрации; поиск без `login` защищает от перебора логинов; один `PeopleSearch` с действием на строке обслуживает и новый чат, и приглашение.
- **Альтернативы (не выбраны):** клиентская фильтрация `GET /api/users` (утечка списка пользователей); модалка «Новый чат» из хедера (выбран поиск в левой панели, как в Telegram); группа с обязательным ≥1 участником (бэкенд разрешит пустую); приглашения с согласием приглашённого (отложены в бэклог).

## FE-D46 — Отправка сообщений: ретраи, статусы иконками, лимит длины, local-чаты (2026-10-17)
- **Решение (выбор пользователя):** (1) автоповтор на сеть/`5xx`/`429` — 3 попытки с экспоненциальным backoff 1 с → 2 с → 4 с и джиттером (при `429` пауза из `Retry-After`), затем `failed`; уточняет число попыток из FE-D15(1). (2) Статус своего сообщения — иконка рядом с ним, как в Telegram: часы (`sending`), одна галочка (`sent`), красный треугольник с «!» внутри (`failed`) — это кнопка (курсор-указатель, ховер, видимый фокус), нажатие на неё — «Повторить» с тем же `clientId`; у иконок доступное имя («Отправляется», «Отправлено»; у кнопки — «Не отправлено. Повторить»). Иконки — inline SVG без библиотеки, цвет через токены темы. Двойная галочка «прочитано» — вне FE-40 (FE-43). (3) Текст длиннее 4000 кодовых точек: Send и Enter не отправляют, над полем счётчик «N / 4000» с `role="alert"`, текст в поле не обрезается. (4) В local-чатах (`local: true`, кнопка Join) отправка остаётся локальной без `POST` и без иконки статуса; JoinForm удаляется в FE-44.
- **Почему:** 3 попытки (~7 с) быстро показывают ошибку и не нагружают сервер; иконки компактнее текста и привычны пользователю; inline SVG не добавляет зависимость ради трёх иконок; блокировка с счётчиком не теряет текст; local-чатов нет на сервере, и `POST` в них всегда вернёт `404`.
- **Альтернативы (не выбраны):** 5 попыток (около 30 с в статусе «отправляется»); без автоповтора (противоречит FE-D15(1)); текстовые статусы; видимая кнопка «Повторить» рядом с иконкой; библиотека иконок (lucide-react); ошибка без счётчика или молчаливое обрезание текста; `POST` в local-чаты со статусом `failed`.
