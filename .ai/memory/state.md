# Состояние frontend
> Проверено: 2026-10-22 @ e38a6df+dirty

## Общее
Ранний прототип UI мессенджера (React 18, CRA, Redux Toolkit). Сетевой слой — auth (`src/app/services/apiClient.js`, `src/app/services/authApi.js`: проверка сессии, вход и регистрация по паролю, выход), список чатов, карточка чата и история сообщений (`src/app/services/chatsApi.js`, `src/app/reducers/chatHistory.js`, FE-38, FE-39: загрузка при открытии серверного чата, подкачка старых — thunk без триггера до FE-27); отправка — только в Redux; бэкенд — отдельный проект `messenger-server`. Тесты: unit (`chats`, `messages`, `Dialog`, `auth`, `store`, `UserMenu`, `apiClient`, `authApi`, `App`, `tokens`, `useTheme`, `Login`, `Button`, `IconButton`, `Input`, `Avatar`, `globalStyles`), e2e: `smoke`, `chats`, `tokens`, `theme`, `ui-primitives`, `messages`, `login` (сессия после перезагрузки, сбой проверки сессии, тёмная тема экрана входа), `password-auth` (вход и регистрация по паролю, FE-89), `login-errors`, `login-validation`, `logout`, `session-closed` (сессия закрыта вне вкладки, FE-35), mock-BFF proxy и контрактные (контрактные в приёмке пропускаются без `MOCK_BFF_URL` — FE-53); вход и имя пользователя в e2e — через общий хелпер `e2e/helpers/auth.js` (FE-58; с FE-89 — форма логина и пароля, засеянный `alice` mock-BFF).

## Что работает
- Redux store с пятью слайсами, нормализованными по разделу 4 `docs/client-integration.md` (FE-37): `chats` и `users` (`createEntityAdapter`), `messages` (по `chatId`, ключ `seq`), `activeChatId` и `auth` (`status`: loading/anonymous/authenticated/error/sessionClosed + `user` по модели `SessionUser`, thunks `checkSession`, `logout`, событие `sessionClosed`); UI читает store через селекторы; список чатов загружается с `GET /api/chats` (thunk `fetchChats`, хук `src/app/modules/messenger/useChatsLoader.js`, FE-38; ответ заменяет список целиком), создание direct-чата — `createDirectChat` (FE-44), отправка локальная (события `chatSelected`/`usersReceived`, отправка — thunk `sendMessage` с `seq = lastSeq + 1`, событие `messageAdded` в `reducers/messageEvents.js`); сеть есть для списка, карточки чата и истории (FE-38, FE-39), отправка пока локальная (FE-40); `rootReducer` сбрасывает весь store на `logout.fulfilled` и на `sessionClosed` (только у вошедшего)
- Realtime (FE-41): `services/wsService.js` (`createWsService`: статусы connecting/open/reconnecting/displaced/closed, backoff с full jitter, коды 4008/4401/1006/1001, без импорта store), слайс `reducers/realtime.js` (статус, thunks `startRealtime`/`pauseRealtime`/`resumeRealtime`, обработка `message.new`/`chat.created`/`chat.updated`/`chat.removed`, догонка `since`, дедуп по (`chatId`, `seq`); FE-42: на каждый `open`, кроме первого, при загруженном списке чатов — сверка `reconcileChats` (`GET /api/chats`, подкачка `since` у выросших чатов, слияние `chatsReconciled` без потери `history`, удаление исчезнувших; одна сверка, новая отменяет прежнюю); `nudgeRealtime` → `retryNow` сервиса по `online`/`visibilitychange` в `useRealtime`); сервис — модульная переменная в `realtime.js`; хук `useRealtime` и баннер `RealtimeBanner` (4008, «Подключиться») в `Messenger`; `UserMenu` закрывает сокет до `logout`
- `src/app/services/apiClient.js` и `authApi.js` (`fetchSession`, `login`, `register`, `logout`); csrfToken хранится только в apiClient; `403 csrf_invalid` → перечитывание сессии (хук `setCsrfRecoveryHandler`, `recoverCsrf` в `reducers/auth.js`) и один повтор запроса, при смене `user.id` store сбрасывается действием `userSwitched` (FE-96)
- Левая панель: поле «Поиск людей» над списком чатов (`useUserSearch`: ≥2 символа, debounce 300 мс, abort; `PeopleSearch`), по «Написать <имя>» — `createDirectChat` (POST /api/chats direct, существующий чат открывается без дубля; ошибки «Пользователь недоступен» / «Не удалось открыть чат.») (FE-44). Хедер: кнопка с аватаром и именем пользователя → выпадающее меню `UserMenu`: переключатель темы (светлая / тёмная / как в системе), «Выйти», закрытие по Esc и клику снаружи (FE-15, FE-28)
