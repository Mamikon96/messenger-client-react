# FE-67 (P2)

Админка: раздел виден только администратору — после входа `GET /api/admin/users`: `200` → пункт входа в раздел и раздел, `403 forbidden` → раздела нет (флага админа в сессии нет, SH-D12); адрес раздела (зависит от ответа по FE-59), место пункта (меню пользователя пересекается с FE-28) и поведение при прямом заходе не-админа — уточнить у пользователя; mock-BFF: признак админа у засеянного пользователя (FE-88), `GET /api/admin/users` с `AdminUserItem` (`id`, `login`, `firstName`, `lastName`, `name`, `avatarUrl`, `isAdmin`, `disabledAt`; спека `docs/auth-password-spec.md` §2.8, §3). Первый админ на реальном сервере — CLI `npm run admin:promote <login>` (BE-34). Кейсы: UC-ADMIN-01 (перевод в active — с разрешения пользователя). Проверка: `npx playwright test -g "UC-ADMIN-01"` (админ и обычный пользователь) и unit падают до реализации. Критерий: `npm run accept` = 0. Зависит от: FE-59 (если роутер остаётся), FE-89. На реальном сервере — после BE-34. P2, а не P1: при открытой регистрации админка не нужна для появления новых пользователей (переформулирована FE-85, 2026-10-13).
