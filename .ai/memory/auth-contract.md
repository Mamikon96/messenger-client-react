# Контракт auth API
> Источник: FE-D04, FE-D05 (`decisions.md`), задача FE-09. Бэкенда пока нет: контракт реализует mock-BFF (FE-10), фронт — `apiClient`/`authApi` (FE-12, FE-13). Менять контракт — только по решению пользователя, с записью в `decisions.md`.

## Общее
- SPA и API на одном сайте; все пути — относительные, под префиксом `/api/auth`.
- Провайдеры: `google`, `github` (значение `{provider}` в пути).
- Сессия — cookie `HttpOnly; Secure; SameSite=Lax`, её ставит и читает только сервер. Фронт токенов и session id не видит; запросы шлются с `credentials: 'same-origin'`.
- Абсолютный срок сессии — 7 дней, без idle-таймаута и «запомнить меня». По истечении любой запрос с сессией отвечает `401`.
- CSRF: токен приходит в теле `GET /api/auth/session`, фронт хранит его только в модуле `apiClient` (не в Redux, не в localStorage) и шлёт в заголовке `X-CSRF-Token` на изменяющие запросы (`POST`, `PUT`, `PATCH`, `DELETE`).
- Тела — JSON (`Content-Type: application/json`), кроме редиректов.

## Эндпоинты
| Метод и путь | Назначение | Ответы |
|---|---|---|
| `GET /api/auth/{provider}/start` | Начало входа. Вызывается **полной навигацией** браузера (не `fetch`). Сервер генерирует state и PKCE и отвечает редиректом на провайдера | `302` на провайдера; неизвестный `{provider}` — `404` |
| `GET /api/auth/{provider}/callback` | Возврат от провайдера. Сервер меняет код на токены, создаёт сессию, ставит cookie | `302` на `/` (успех) или на `/?auth_error=<код>` (ошибка) |
| `GET /api/auth/session` | Текущая сессия; фронт вызывает при старте приложения | `200` с телом ниже; `401` — сессии нет или она истекла |
| `POST /api/auth/logout` | Выход: сервер инвалидирует сессию. Требует `X-CSRF-Token` | `2xx` без тела; `401` — сессии нет; `403` — неверный CSRF-токен |

### Тело `200` для `GET /api/auth/session`
```json
{
  "user": { "id": "string", "name": "string", "avatarUrl": "string", "provider": "google | github" },
  "csrfToken": "string"
}
```
Поля `user` — ровно эти четыре; email не передаётся.

### Ошибка входа: `/?auth_error=<код>`
| Код | Когда |
|---|---|
| `access_denied` | пользователь отказался у провайдера |
| `provider_error` | провайдер вернул ошибку или код не удалось обменять |
| `invalid_state` | state не совпал или устарел |

Фронт читает параметр, показывает сообщение на экране входа и убирает параметр из URL через `history.replaceState`. Тексты сообщений — решает FE-17. Возврата на исходную страницу (`returnTo`) нет: после входа всегда `/`.

## Коды ответов для остальных `/api/*`
- `401` — сессии нет или она истекла: фронт сбрасывает store и показывает экран входа с сообщением «сессия истекла» (FE-16).
- `403` — запрос отклонён (в том числе неверный или отсутствующий CSRF-токен): это **не** выход из сессии.
- Сетевая ошибка не равна `401`.

## Не определено (решается в соответствующих задачах)
- Имя cookie и формат тела ошибок кроме указанных — детали сервера, фронту не нужны.
- Тексты UI (кнопки, сообщения об ошибках, «сессия истекла») — FE-14, FE-16, FE-17.
- Связывание аккаунтов Google и GitHub одного человека — не требуется, пока не решено иначе.
