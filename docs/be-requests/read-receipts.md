# Запрос к бэкенду: статус «прочитано собеседником»

Нужен для статуса сообщения «прочитано» (две галки) в клиенте (FE-113). Сейчас клиент показывает только «отправлено» (одна галка), потому что чужое прочтение недоступно (`docs/client-integration.md` §8б.1, связано с BE-20).

## Что требуется
1. **Прочтение участников в списке чатов.** В `ChatListItemDto` добавить `readSeq: number`: для direct — `last_read_seq` собеседника, для group — минимальный `last_read_seq` среди остальных участников. Клиент считает своё сообщение прочитанным, если `message.seq <= readSeq`. Открытый вопрос бэкенду: допустимая альтернатива — `lastReadSeq` в `ChatMemberDto`, тогда имя поля согласовать до начала FE-160.
2. **Событие в реальном времени.** WebSocket-событие `chat.read` с полезной нагрузкой `{ chatId, userId, seq }`, рассылаемое участникам чата при `POST /api/chats/:id/read` (только если `last_read_seq` вырос). Своим вкладкам событие тоже приходит: это закрывает и пункт §8б.2 (синхронизация собственного прочтения между вкладками).
3. **Догонка при реконнекте.** После переподключения значения доступны через `GET /api/chats` (п. 1); отдельная догонка событий не нужна.
4. **Приватность.** Решение владельца продукта: показывать ли прочтение всегда или дать отключить («скрыть статус прочтения»). Клиент готов к отсутствию поля: тогда остаётся одна галка.

## Критерии для бэкенда
- Поле и событие описаны в контракте (`docs/client-integration.md`), есть тесты на рост `last_read_seq` и рассылку.
- Отправка своего сообщения тоже двигает `last_read_seq` отправителя — событие `chat.read` должно приходить и в этом случае либо поле в списке должно отражать это.
