# Решения: Процесс: правила для агентов

Формат записи и правила — `../decisions.md`. Записи до FE-D51 перенесены из исходного `decisions.md` без изменений.

## SH-D05 — Решение фиксируется сразу после выбора пользователя; пишет solution-architect (2026-10-05)
- **Решение:** после ответа пользователя на `AskUserQuestion` решение с обоснованием («Решение / Почему / Альтернативы») записывается в `decisions.md`: если варианты готовил `solution-architect` — он сам (ему выдан `Edit` только для `decisions.md`, основная сессия передаёт ему выбор через `SendMessage`), иначе основная сессия. Уточняет FE-D03: согласием на запись считается сам выбор, запись не откладывается до конца реализации.
- **Почему:** агенты читают готовые решения и не изобретают их заново; причины фиксируются, пока свежи, а не после реализации; архитектор лучше всех знает, почему отклонены альтернативы.
- **Альтернативы:** запись основной сессией после реализации (прежний порядок — решения теряются или теряют контекст); отдельный вопрос «записывать ли?» (лишний шаг, выбор уже есть).

## SH-D06 — Жёсткое правило для всех агентов: сомнение или нехватка данных → вопрос пользователю (2026-10-05)
- **Решение:** любой агент при сомнении или нехватке данных спрашивает пользователя и ничего не придумывает (требования, поведение, значения, причины багов, факты о коде). Правило в `.ai/rules/ask-user.md`, п. 6 «Неснимаемых правил» `CLAUDE.md`, блок «Жёсткое правило» в каждом агенте `~/.claude/agents/*`. Агент без `AskUserQuestion` (ревьюеры, фоновые) возвращает вопросы вызывающему, основная сессия переадресует их пользователю.
- **Почему:** догадки агентов дают неверные требования и незаметные ошибки; цена вопроса ниже цены переделки.
- **Альтернативы:** правило только в `CLAUDE.md` (агенты вне проекта его не увидят); допущения «по умолчанию» с пометкой в отчёте (всё равно строит работу на выдумке).

## FE-D03 — Процесс: память после любых изменений и согласование технологий (2026-10-05)
- **Решение:** (1) после любых изменений, до ответа пользователю, актуализируется `tasks.md` (и при необходимости `state.md`/`architecture.md`, штамп); (2) новая технология, библиотека или подход применяются только после опроса пользователя, а запись в decisions — только после его согласия; (3) `scripts/check-memory.sh` падает, если изменённые относительно HEAD файлы кода (`src/`, `e2e/`, `scripts/`, `package.json`, `playwright.config.js`) новее `tasks.md`.
- **Почему:** требование владельца проекта: память всегда актуальна, а выбор технологий остаётся за ним; проверка по времени изменения даёт механическую защиту от забытых обновлений.
- **Альтернативы:** обновлять память только по завершении задачи (риск устаревших данных между этапами); записывать решения автоматически (отвергнуто — решает владелец); проверка свежести через хук коммита (не выбрано: сложнее и срабатывает позже).
