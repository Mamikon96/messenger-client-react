# Git: коммиты и ветки (git-flow)
Читать: перед ЛЮБОЙ git-операцией — коммит, ветка, слияние, тег, push, PR.
Источник: `scripts/git-task.sh` исполняет «Автоматический цикл»; решения пользователя по веткам и PR. Пересмотреть, когда меняется `git-task.sh` или модель веток. Шпаргалка (FE-141): подробности проверок — в самом скрипте, его сообщения об ошибках самодостаточны.

## Правила
- Ветка задачи, коммит, push и PR — автоматически. Слияние, теги, удаление веток, `--amend` — только по явной просьбе; разрешение на одно действие не распространяется на другое.
- Запрещено без явного «да»: `--force`, `reset --hard`, `--no-verify`, `--amend` опубликованных коммитов. `git add -A` запрещён всегда: файлы добавлять по именам; файлы, пропущенные через `--allow-dirty`, не коммитятся. Прямые коммиты в `main` и `develop` запрещены (кроме слияний).
- Не коммитить секреты, `.env`, `node_modules`, `build/`, `test-results/`, `playwright-report/`.
- Перед коммитом: память актуальна, `bash scripts/check-memory.sh` = 0, `git status` + `git diff --staged --stat`, затем дифф файлов, где возможны секреты или лишнее; в коммит только файлы задачи.

## Автоматический цикл (`bash scripts/git-task.sh`; ничего не сливает)
1. **Старт** — первым шагом, до правок: `start FE-NN <slug>` (баг: третьим аргументом `bugfix`; вне бэклога: `start chore <slug>`). Скрипт проверяет репозиторий, задачу в `tasks.md`, чистоту дерева, базу (`develop`, иначе `main`), `check-memory.sh`; затем создаёт `feature/FE-NN-<slug>` или переключается на существующую. Ошибку не обходить: исправить причину или спросить пользователя; `--allow-dirty` — только с согласия пользователя. Несколько задач — отдельная ветка и коммит на каждую.
2. **Завершение** — только после `acceptance.md` (`npm run accept` = 0 и APPROVE, где нужен) и обновления памяти: `git-task.sh commit "<type(scope): описание>" -- <файлы явно, включая .ai/memory/…>`. Один коммит на задачу; WIP-коммитов нет.
3. **PR** — сразу после коммита: `git push -u origin <ветка>`, `gh pr create --base develop` (`release/*`, `hotfix/*` — в `main`). Заголовок как у коммита; без строки «Generated with Claude Code»; тело: что сделано, коммиты, проверка. Слияние PR — по просьбе; ветка удаляется при слиянии автоматически (`develop` и `release/*` защищены). В отчёте: ветка, хеш, ссылка на PR.

## Ветки
| Ветка | Откуда → куда | Назначение |
|---|---|---|
| `main` | — | стабильная, только релизы и hotfix |
| `develop` | `main` → `release/*` | интеграция готовых фич; push только через PR |
| `feature/FE-NN-slug`, `bugfix/FE-NN-slug`, `chore/slug` | `develop` → `develop` | одна задача; `chore` — работа вне бэклога |
| `release/x.y.z` | `develop` → `main` и `develop` | стабилизация: только багфиксы, версия, документация |
| `hotfix/x.y.z-slug` | `main` → `main` и `develop` | срочное исправление |

Имя ветки: латиница, нижний регистр (кроме `FE-NN`), слова через `-`. Слияние `feature/*`, `bugfix/*` в `develop` — PR, `--no-ff`, условие: `npm run accept` = 0 и APPROVE `react-reviewer`. `release/*`, `hotfix/*` → `main` с `--no-ff`, затем аннотированный тег `git tag -a vX.Y.Z -m "Release X.Y.Z"` и слияние обратно в `develop`. SemVer.

## Сообщения коммитов (Conventional Commits)
`<type>(<scope>): <описание>`; scope необязателен (модуль или слайс: `chats`, `login`, `store`, `e2e`).
- `type`: `feat` · `fix` · `refactor` · `test` · `docs` · `style` · `perf` · `build` · `ci` · `chore` · `revert`.
- Описание: повелительное наклонение, до ~72 символов, без точки, по-русски; идентификаторы и команды как в коде.
- Тело (опционально): зачем, а не что. Ссылка `Refs: FE-02`. Breaking: `!` после типа и футер `BREAKING CHANGE: …`. Футер `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` последней строкой добавляет `git-task.sh commit` сам (переопределение — переменная `GIT_TASK_COAUTHOR`, пустая — без футера; своя строка `Co-Authored-By:` в сообщении не дублируется) — вручную не писать.
- Примеры: `feat(messages): отправка сообщения из Dialog по Enter` · `fix(login): инвертировать условие показа формы входа`.
