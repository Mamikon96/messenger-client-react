# Память проекта для AI

Проект — только frontend (бэкенд `messenger-server` — отдельный проект, SH-D04; контракт — `docs/client-integration.md`, локальная копия вне git, FE-D12). Общий индекс — `.ai/README.md`; правила работы с памятью — `.ai/rules/memory-protocol.md`.

```
.ai/memory/
  README.md          # этот файл
  tasks.md  state.md
  architecture.md    # роутер: «что делаешь → файл»
  architecture/      # карта кода по темам: data-flow, store, components, ui-primitives, styles-theme, services, mock-bff
  done.md            # архив «Сделано»
  decisions.md       # действующие решения проекта: SH-Dxx (общие) и FE-Dxx (frontend)
  decisions-archive.md  # заменённые решения (ЗАМЕНЕНО), без изменений
  backlog/           # подробности задач бэклога: FE-NN.md; README.md — контекст решений по бэклогу
  product-agreements.md  # соглашения по продукту и бэкенду
  failures.md        # журнал провалов (REJECT/FAIL, лимит раундов)
```

## Файлы
| Файл | Что хранит | Когда читать | Как обновлять |
|---|---|---|---|
| tasks.md | В работе (с контрактом) / Бэклог (индекс: строка ≤200 символов, подробности — `backlog/FE-NN.md`, FE-D41) | всегда при задаче разработки | Двигать задачи между секциями; длинное описание — в `backlog/FE-NN.md` |
| backlog/FE-NN.md | Подробности одной задачи бэклога | когда задачу берут в работу | Создавать при заведении задачи с описанием длиннее строки; строка в `tasks.md` обязательна |
| done.md | Архив «Сделано»: закрытые задачи с датой, приёмкой, ревью (FE-D27) | только за историей, поиском по ID | Добавлять в конец при закрытии задачи |
| state.md | Текущее состояние, известные проблемы (с путями к коду), последняя приёмка, фокус | баги, регрессии, выбор следующей задачи | Перезаписывать целиком только после сверки с кодом |
| architecture.md | Роутер: таблица «что делаешь → файл `architecture/*.md`» (FE-125) | новые модули, правка структуры; затем читать только нужный файл из таблицы | Новый файл папки — строка в таблице (проверяет `check-memory.sh`) |
| architecture/*.md | Карта кода и потоки данных по темам | только файл по теме задачи | Править при изменении структуры; штамп — в каждом файле, обновлять после сверки с кодом именно этого файла |
| decisions.md | Действующие решения: что, почему, альтернативы (`SH-Dxx` — процесс, приёмка, память, продукт; `FE-Dxx` — frontend) | архитектурный выбор, новая технология, вопросы процесса (искать по заголовкам `## FE-Dxx` / `## SH-Dxx`, не читать целиком) | Только добавлять в конец; заменённое (ЗАМЕНЕНО, не ЧАСТИЧНО) переносится в `decisions-archive.md` целиком |
| decisions-archive.md | Заменённые решения с пометкой «ЗАМЕНЕНО» | только за историей | Переносить без изменений; ID не повторяются с `decisions.md` |
| failures.md | Журнал провалов: дата, задача, симптом, слой, исправление в харнесе (FE-D23) | REJECT/FAIL, лимит раундов, ревизия харнеса | Только добавлять строки |
| product-agreements.md | Цель, рамки и соглашения по продукту, архитектуре и бэкенду (вход для отдельного проекта бэкенда) | проектирование контракта API/событий, реалтайм, серверное хранение | Менять только по решению пользователя (запись в `decisions.md`) |

## Правила актуальности и корректности
- Первая строка после заголовка в `state.md`, `tasks.md`, `architecture.md` и каждом `architecture/*.md`: `> Проверено: ГГГГ-ММ-ДД @ <git sha>[+dirty]` — дата и коммит, на которых факты сверены с кодом. Обновляется **только** после реальной сверки.
- Каждое утверждение о проблеме/состоянии содержит путь к коду в обратных кавычках и проверено чтением кода, `grep` или запуском — не по памяти и не по прошлой записи.
- Исправленное из «Известных проблем» удаляется (история — в git и `done.md`).
- Задача в «В работе» всегда содержит блок «Осталось»; в архиве `done.md` — дату и результат приёмки.
- ID: задачи `FE-NN` (следующий — максимальный по `tasks.md` и `done.md` + 1), решения `FE-DNN` / `SH-DNN`. ID не переиспользуются (в том числе после удаления задачи).
- Даты — абсолютные `ГГГГ-ММ-ДД`. Не хранить секреты и то, что очевидно из кода/git.
- Механическая проверка: `bash scripts/check-memory.sh` (входит в `bash scripts/check-state.sh` и `npm run accept`).
- Источник истины о поведении продукта — `docs/user-cases.md` (не часть памяти; менять только с разрешения пользователя, FE-D16); отчёты тестировщика — `.qa/runs/<задача>.md` (вне git, FE-D17, FE-D36).
