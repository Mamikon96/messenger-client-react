# FE-94 (P2)

Смена пароля в настройках (`POST /api/me/password`, `docs/client-integration.md` §3.13): текущий и новый пароль, проверка нового до отправки (12..256 байт UTF-8, как в FE-92); `204` — сообщение об успехе, сессия и `csrfToken` остаются; `401 auth_failed` — «Неверный текущий пароль», из системы не выходит (FE-56); `400 validation_failed` — ошибка у поля нового пароля по `details`; `429` — с `Retry-After`; mock-BFF: `POST /api/me/password` удаляет остальные сессии пользователя, контрактные тесты. Кейсы: UC-PROFILE-02 (перевод в active — с разрешения пользователя). Проверка: unit и e2e по кейсу (другая сессия после смены получает `401`) падают до реализации. Критерий: `npm run accept` = 0. Зависит от: FE-56, FE-92, FE-93. На реальном сервере — после BE-39, BE-40.
