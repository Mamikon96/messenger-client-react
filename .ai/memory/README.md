# Память проекта для AI

Проект — только frontend (бэкенд `messenger-server` — отдельный проект, SH-D04; контракт — `docs/client-integration.md`, локальная копия вне git, FE-D12). Общий индекс — `.ai/README.md`; правила работы с памятью — `.ai/rules/memory-protocol.md`.

```
.ai/memory/
  README.md          # этот файл
  tasks.md  state.md  architecture.md
  decisions.md       # все решения проекта: SH-Dxx (общие) и FE-Dxx (frontend)
  auth-contract.md   # история контракта auth (FE-09); источник истины — docs/client-integration.md
  product-agreements.md  # соглашения по продукту и бэкенду
```

## Файлы
| Файл | Что хранит | Когда читать | Как обновлять |
|---|---|---|---|
| tasks.md | В работе (с «Осталось») / Бэклог / Сделано (с датой и приёмкой) | всегда при задаче разработки | Двигать задачи между секциями |
| state.md | Текущее состояние, известные проблемы (с путями к коду), последняя приёмка, фокус | баги, регрессии, выбор следующей задачи | Перезаписывать целиком только после сверки с кодом |
| architecture.md | Карта кода и потоки данных | новые модули, правка структуры | Править при изменении структуры |
| decisions.md | Все решения: что, почему, альтернативы (`SH-Dxx` — процесс, приёмка, память, продукт; `FE-Dxx` — frontend) | архитектурный выбор, новая технология, вопросы процесса (искать по заголовкам `## FE-Dxx` / `## SH-Dxx`, не читать целиком) | Только добавлять в конец |
| auth-contract.md | История контракта auth (FE-09); заменён `docs/client-integration.md` (FE-D12) | только за историей; контракт API — в docs | Не менять |
| product-agreements.md | Цель, рамки и соглашения по продукту, архитектуре и бэкенду (вход для отдельного проекта бэкенда) | проектирование контракта API/событий, реалтайм, серверное хранение | Менять только по решению пользователя (запись в `decisions.md`) |

## Правила актуальности и корректности
- Первая строка после заголовка в `state.md`, `tasks.md`, `architecture.md`: `> Проверено: ГГГГ-ММ-ДД @ <git sha>[+dirty]` — дата и коммит, на которых факты сверены с кодом. Обновляется **только** после реальной сверки.
- Каждое утверждение о проблеме/состоянии содержит путь к коду в обратных кавычках и проверено чтением кода, `grep` или запуском — не по памяти и не по прошлой записи.
- Исправленное из «Известных проблем» удаляется (история — в git и «Сделано»).
- Задача в «В работе» всегда содержит блок «Осталось»; в «Сделано» — дату и результат приёмки.
- ID: задачи `FE-NN`, решения `FE-DNN` / `SH-DNN`. ID не переиспользуются (в том числе после удаления задачи).
- Даты — абсолютные `ГГГГ-ММ-ДД`. Не хранить секреты и то, что очевидно из кода/git.
- Механическая проверка: `bash scripts/check-memory.sh` (входит в `npm run accept`).
