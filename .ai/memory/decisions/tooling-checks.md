# Решения: Инструменты и проверки

Формат записи и правила — `../decisions.md`. Записи до FE-D51 перенесены из исходного `decisions.md` без изменений.

## FE-D24 — ESLint в приёмке для `src`, `e2e`, `scripts`, `mock-bff` с overrides по типу тестов (2026-10-12)
- **Решение:** `npm run accept` запускает `npx eslint src e2e scripts mock-bff --max-warnings=0` сразу после статических проверок. В `eslintConfig` (`package.json`) — `overrides`: для `e2e/**` отключены правила `testing-library/*` и `jest/*` (это Playwright, не Testing Library/Jest), для `scripts/**/*.test.js` — `no-template-curly-in-string` (строки с `${…}` там — тестовые данные). Подавление правил комментариями `eslint-disable` в коде не используется.
- **Почему:** выбор пользователя по FE-49 (аудит харнеса, P2.1): статический слой проверки отсутствовал — 9 ошибок в unit-тестах `src` не ловились приёмкой. Пресет `react-app/jest` применяет правила Testing Library/Jest ко всем `*.spec.js`/`*.test.js`, что даёт 67 ложных срабатываний в Playwright-тестах и тестах чекера.
- **Альтернативы:** линтить только `src` (e2e и скрипты без статической проверки); отдельный конфиг для `e2e` с `eslint-plugin-playwright` (точнее правила, но новая зависимость); не выбраны.

## FE-D25 — Архитектурные правила проекта исполняются правилами ESLint (2026-10-13)
- **Решение:** механизируемые правила `.ai/rules/patterns.md` и `.ai/rules/code-style.md` проверяет ESLint через `overrides` в `eslintConfig` (`package.json`): `no-restricted-imports` — `src/app/services/` и `src/app/reducers/` не импортируют `modules/`, слайсы не импортируют `store`; `no-restricted-globals`/`no-restricted-properties` — `fetch` только в `src/app/services/` (тесты исключены); `no-restricted-syntax` — без `console.log` в `src/`. Каждое правило с сообщением «почему / как исправить». Поведение правил закреплено тестом `scripts/eslint-rules.test.js` (ESLint API, `lintText` по зонам). Механизированные пункты в `patterns.md`/`code-style.md` заменены ссылкой на проверку. Существующие `console.log` в `Chats.js` и `JoinForm.js` удалены в той же задаче (FE-50).
- **Почему:** выбор пользователя по FE-50 (аудит харнеса, P2.2): ESLint уже в приёмке (FE-D24), понимает импорты, а не текст, без новых зависимостей; правило в тексте проверял только ревьюер, что стоило раундов ревью.
- **Альтернативы:** скрипт arch-check.sh с grep-гвардами (второй механизм рядом с ESLint, поиск по тексту с ложными срабатываниями); временное исключение файлов с `console.log` до FE-26/FE-44 (исключение легко забыть снять); не выбраны.

## FE-D26 — Тесты `scripts/` (node:test) без правил Jest и Testing Library в ESLint (2026-10-13)
- **Решение:** дополняет FE-D24: для `scripts/**/*.test.js` в `overrides` выключены те же правила `jest/*` и `testing-library/*`, что и для `e2e/**`, плюс `no-template-curly-in-string`.
- **Почему:** выбор пользователя по замечанию ревью FE-49: это тесты `node:test`, а не Jest; правила пресета `react-app/jest` дали бы ложные срабатывания на будущих тестах чекеров.
- **Альтернативы:** оставить только `no-template-curly-in-string` и расширять по факту ложных срабатываний; не выбрано.

## FE-D27 — Объём второй части аудита харнеса (FE-52) (2026-10-13)
- **Решение:** в FE-52 входят все четыре части: архив «Сделано» из `tasks.md` в отдельный файл памяти (читается только за историей); hooks `SessionStart` (сводка: ветка, «В работе», фокус, последняя приёмка) и `Stop` (проверка памяти с возвратом агенту при ошибке) в `.claude/settings.json`; штамп приёмки с хэшем дерева, по которому ревьюер не перезапускает приёмку при совпадении; синхронизация `state.md` с кодом и единый маршрутизатор (таблица — только в `CLAUDE.md`).
- **Почему:** выбор пользователя (аудит `docs/ai-harness-audit.md`, P2.3, P2.4, P3.1, P3.3): меньше чтения на старте задачи, механическая гарантия обновления памяти, ревьюер не повторяет приёмку и не конфликтует с `qa-tester` за порты (случилось в FE-49).
- **Альтернативы:** выполнить часть пунктов или отложить; не выбрано.

## FE-D28 — Контрактные тесты mock-BFF выполняются в приёмке (FE-53) (2026-10-13)
- **Решение:** `e2e/mock-bff.contract.spec.js` получает адрес mock-BFF, который поднимает Playwright в `npm run accept`, и выполняется в приёмке; условный `test.skip` всего файла убирается. Если тесты окажутся красными из-за расхождения mock-BFF с `docs/client-integration.md`, каждое расхождение — вопрос пользователю.
- **Почему:** выбор пользователя по FE-53: файл фактически не выполнялся, что противоречит запрету `test.skip` в `.ai/rules/testing.md` и оставляет контракт mock-BFF без проверки.
- **Альтернативы:** удалить спек как устаревший (контракт auth заменён `docs/client-integration.md`); зафиксировать исключение в `testing.md`; не выбраны.
