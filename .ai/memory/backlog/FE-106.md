# FE-106 (P3)

`src/app/reducers/chats.js` (проверка `requestId` в payload-creator) и `src/app/reducers/users.js` (extraReducer на `fetchChats.fulfilled`): между проверкой `getState().chats.requestId` после `await` и диспатчем `fulfilled` есть несколько микротасков RTK; если в это окно другой запрос получит 401 и вызовет `sessionClosed`, `chats` ответ отсечёт по `requestId`, а `users` запишет собеседников в сброшенный слайс (без показа). Гипотеза из ревью FE-38 (раунд 2), не воспроизведена. Возможное исправление — одна проверка в `rootReducer` или сверка `requestId` в `users`; сначала unit-тест на сценарий. Критерий: `npm run accept` = 0.
