# Решения: Вход и регистрация по логину и паролю

Формат записи и правила — `../decisions.md`. Записи до FE-D51 перенесены из исходного `decisions.md` без изменений.

## FE-D38 — Вход и регистрация по логину/паролю (2026-10-13)
- **Решение (выбор пользователя):** контракт — итоговый `docs/client-integration.md` (до FE-98 — локальная спека `docs/auth-password-spec.md`, удалена); решения бэкенда — SH-D18, BE-D31…BE-D34 в `messenger-server`. OAuth и задел passkey/инвайтов в клиенте удаляются. Форма входа и регистрации — логин и пароль; имя при регистрации не спрашивается (генерирует сервер), меняется в настройках (`firstName`/`lastName`). Выход из системы — только при `401 unauthorized`; `401 auth_failed` — ошибка формы. Ошибки полей показываются по `error.details`. После `403 csrf_invalid` — один повтор запроса. Заменяет FE-D04 в части «вход только через OAuth; email+пароль не делаем», а также FE-D06, FE-D30, FE-D32, FE-D33, FE-D34.
- **Почему:** бэкенд перешёл на открытую регистрацию и вход по логину/паролю (SH-D18), инвайты и passkeys удалены; разделение `unauthorized`/`auth_failed` не выкидывает пользователя из сессии при ошибке ввода.
- **Альтернативы (не выбраны):** поле имени в форме регистрации; сохранение входа по passkey как второго способа.

## FE-D39 — Уточнения к переходу на пароли после планирования FE-85 (2026-10-13)
- **Решение (выбор пользователя):**
  - На переходный период (до BE-42) `scripts/check-state.js` брал эндпоинты входа по паролю из `docs/auth-password-spec.md` (вариант Б в FE-86); в FE-98 сверка убрана, источник — только `docs/client-integration.md`.
  - `react-router` (FE-D31) остаётся: настройки профиля — маршрут `/settings` с пунктом в меню пользователя, админка — отдельный маршрут.
  - Новым user-кейсам — новые ID, старые не переиспользуются; UC-AUTH-09 остаётся в новой формулировке (вход отключённого пользователя по паролю).
  - mock-BFF отклоняет частые пароли (`too_common`) по короткому списку.
  - «Выйти на всех устройствах» — с подтверждением.
  - В `auth-contract.md` (удалён, FE-D50) допустима одна строка-указатель на новую спеку, остальное не меняется (заменено FE-D50).
  - Локальная копия `docs/auth-password-spec.md` удалена в FE-98 (её §12 — план работ клиента).
- **Почему:** вариант А заставил бы клиент ждать самую крупную задачу бэкенда; маршруты настроек и админки оправдывают роутер; переиспользование ID путает историю кейсов; без подтверждения случайный клик разлогинивает все устройства.
- **Альтернативы (не выбраны):** ждать обновления `docs/client-integration.md` бэкендом (вариант А); отказ от роутера и настройки в окне; переиспользование ID кейсов.
