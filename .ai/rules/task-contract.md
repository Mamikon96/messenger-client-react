# Контракт задачи
Читать: при старте любой задачи разработки (после `git-task.sh start`), до тестов и кода; ревьюеру и `qa-tester` — как критерий оценки.
Источник: FE-D20; исполняет `scripts/check-contract.sh`. Пересмотреть, когда меняется состав полей контракта.

Контракт фиксирует, что именно считается выполнением задачи, до первой строки тестов. Источник: аудит харнеса (`docs/ai-harness-audit.md`, P1.1), решение FE-D20.

## Формат
Подпункты под задачей в разделе «В работе» `tasks.md` (все обязательны, пустое значение запрещено; при отсутствии — «нет»):
```
- **FE-NN (P?)** <название>
  - Цель: <одно предложение: наблюдаемое поведение для пользователя/API, не код>
  - Кейсы: <UC-… из набора user-кейсов (docs/user-cases.md + docs/user-cases/), которые задача делает зелёными или не должна сломать> | нет (процесс/инструменты); ID перечислять полностью, без диапазонов «01…05» — по ним `scripts/check-fast.sh` выбирает e2e, а `--require-qa` — объём QA (FE-D35)
  - Проверка задачи: <точные команды, которые падают до реализации и проходят после>
  - В скоупе: <модули/файлы>
  - Вне скоупа: <что не трогать: смежные долги, рефакторинг, стили>
  - Открытые вопросы: нет | <список>
  - Осталось: <следующие шаги>; Не делать: <что уже отвергнуто/опасно>
```
Механическая проверка — `scripts/check-contract.sh` (вызывается из `scripts/check-memory.sh`, значит из `git-task.sh` и `npm run accept`).

## Правила
- Контракт пишет основная сессия при переносе задачи в «В работе». Тесты и код не начинаются, пока «Открытые вопросы» не равны «нет»: вопросы — пользователю (`ask-user.md`).
- «Проверка задачи» — специфичная команда (конкретный e2e/unit-файл или `-g "[UC-…]"`), а не только `npm run accept`: глобальная приёмка проверяет отсутствие регрессий, а не выполнение задачи.
- Замеченное вне скоупа — в «Бэклог», не в код.
- `react-engineer`, `react-reviewer`, `qa-tester` получают контракт в промпте; изменения вне скоупа — замечание ревью.
- Контракт меняется по ходу работы только с согласия пользователя; исполнитель обновляет только «Осталось / Не делать».
- При остановке по лимиту контекста «Осталось / Не делать» — передача смены: следующая сессия продолжает по ним, ничего не переоткрывая.
