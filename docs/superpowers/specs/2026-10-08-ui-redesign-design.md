# Редизайн UI: темы, адаптив, экран входа

Дата: 2026-10-08. Решения: FE-D07…FE-D10 (`.ai/memory/decisions.md`).

## Цель
Современный аккуратный UI мессенджера с продуманным UX и переключением тем (светлая / тёмная / «как в системе»). Дизайн рассчитан на вход через сторонние сервисы (OAuth Google/GitHub уже работает, FE-14/FE-15) и добавление новых провайдеров без правок вёрстки.

## Ограничения
- React 18 + CRA, JavaScript, обычный CSS по БЭМ, один CSS на компонент (`code-style.md`). Новых зависимостей нет (FE-D07).
- Тесты пишутся до реализации; приёмка — `npm run accept` = 0 и APPROVE `react-reviewer`.
- Данные пользователя приходят из `auth.user` (`id`, `name`, `avatarUrl`, `provider`; FE-D06).

## Визуальное направление (FE-D09)
Спокойный минимализм в духе Linear / Telegram Web: тонкие границы, один акцентный цвет, мягкие радиусы, сдержанные анимации. Анимации отключаются при `prefers-reduced-motion`. Контраст не ниже WCAG AA в обеих темах.

## Архитектура

### Токены (FE-22)
`src/styles/tokens.css`, подключается в `src/index.js`. Токены — CSS custom properties на `:root` и `[data-theme="dark"]`:
- цвета: поверхности (`--color-bg`, `--color-surface`, `--color-surface-2`), текст (`--color-text`, `--color-text-muted`), границы, акцент (`--color-accent`, `--color-accent-contrast`), статусы (ошибка, успех), цвет «своего» сообщения;
- типографика (семейство, размеры, межстрочный интервал), отступы (шкала 4 px), радиусы, тени, длительности и easing анимаций.
Компоненты используют только токены, цветов-литералов в компонентных CSS нет. Глобальные стили `button` и `input` из `App.css` на этом шаге не трогаются (удаляются в FE-24).

### Темы (FE-23)
- Режимы: `light`, `dark`, `system`; по умолчанию `system` (FE-D08).
- Выбранный режим хранится в localStorage (ключ `theme`); чтение/запись в try/catch. Это настройка интерфейса, при logout не сбрасывается и в сессионный store не входит.
- Применённая тема выставляется атрибутом `data-theme` на `<html>`. Небольшой инлайн-скрипт в `public/index.html` делает это до первой отрисовки (без вспышки).
- Для `system` слушается `matchMedia('(prefers-color-scheme: dark)')`.
- Состояние темы — хук/контекст `useTheme` в `src/app/modules/theme/`; выбор формы (слайс RTK или контекст) делает реализация задачи по `code-style.md`, с тестом до кода.
- Заглушка `_dark` в `Messenger` удаляется.

### UI-примитивы (FE-24)
`src/app/modules/ui/`: `Button` (варианты primary / secondary / ghost, состояние загрузки), `Input`, `IconButton`, `Avatar` (картинка из `avatarUrl`, при её отсутствии или ошибке — инициалы на цвете, выведенном из `id`). Видимый `:focus-visible` из токенов.

### Экраны
- **Вход (FE-25):** список провайдеров — данные (`id`, название, иконка), кнопка = ссылка на `/api/auth/{id}/start`. Состояние «переход…» после клика, блок ошибки OAuth по `auth_error` из контракта (поглощает FE-17). Новый провайдер = новая запись в списке.
- **Каркас и список чатов (FE-26):** сетка двух панелей, `Chat` с аватаром, выделение активного, пустое состояние списка.
- **Диалог (FE-27):** пузыри (свои справа, чужие слева), поле ввода с Enter / Shift+Enter, автопрокрутка к последнему сообщению, подсказки «чат не выбран» / «сообщений пока нет» (поглощает FE-21).
- **Шапка и меню (FE-28):** кнопка с аватаром и именем, в меню — переключатель темы (3 режима), «Выйти». Закрытие по Esc и клику снаружи.
- **Формы и поповеры (FE-29):** `JoinForm`, `Popover`, `Overlay` на примитивах, подписи полей, `id`/`htmlFor`, закрытие по Esc, фокус в поповер и обратно (поглощает FE-03).
- **Адаптив (FE-30):** брейкпоинт ≈ 768 px. Ниже — одна панель за раз (список или диалог), кнопка «назад» в заголовке диалога; активная панель определяется `activeChat`.
- **Полировка (FE-31):** скелетоны загрузки, плавные переходы, проверка контраста AA обеих тем (поглощает FE-08 в части темы).

## Порядок и зависимости
FE-22 → (FE-23, FE-24) → (FE-25, FE-26, FE-28, FE-29) → FE-27 → FE-30 → FE-31. Каждая задача — отдельная ветка, один PR.

## Тестирование
- Unit (Jest + Testing Library): хук темы (режимы, system, localStorage недоступен), примитивы (варианты, состояния, аватар-фолбэк), логика переключения панелей на узком экране.
- E2E (Playwright): переключение темы переживает перезагрузку; тема `system` следует `colorScheme` браузера (`emulateMedia`); экран входа с ошибкой OAuth через mock-BFF; сценарий отправки сообщения в мобильном viewport (список → диалог → назад).
- Контраст: проверка пар «текст/фон» из токенов обеих тем юнит-тестом по вычисленным значениям.

## Вне объёма
Отдельный пакет по клавиатуре/a11y (базовый уровень входит в каждый компонент), акцентные цветовые схемы, новые провайдеры OAuth на бэкенде, новое поведение сообщений и чатов.

## Риски
- Двойной вид UI на время работы (часть экранов старая, часть новая) — снимается порядком задач: токены и примитивы первыми, глобальные стили `button`/`input` удаляются в FE-24 вместе с миграцией использующих их мест.
- Вспышка темы при загрузке — инлайн-скрипт до отрисовки; проверяется e2e.
- Расхождение токенов между темами — единый набор имён, проверка контраста тестом.
