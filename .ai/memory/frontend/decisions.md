## FE-D01 — Redux Toolkit для состояния (до 2026-10-04, зафиксировано из кода)
- **Решение:** глобальное состояние в RTK-слайсах (`chats`, `activeChat`, `users`), id генерируются `nanoid()` на клиенте.
- **Почему:** нет бэкенда; RTK — стандарт для Redux.
- **Альтернативы:** Context/useReducer (не выбраны, причины не зафиксированы).

## FE-D02 — Структура «модуль = папка с компонентом и CSS» (зафиксировано из кода)
- **Решение:** `app/modules/<name>/Name.js + Name.css`, вложенные части в `components/`; БЭМ-классы с модификаторами `_x`.
- **Почему:** локальность стилей и кода без CSS-in-JS.

## FE-D03 — Процесс: память после любых изменений и согласование технологий (2026-10-05)
- **Решение:** (1) после любых изменений, до ответа пользователю, актуализируется `tasks.md` (и при необходимости `state.md`/`architecture.md`, штамп); (2) новая технология, библиотека или подход применяются только после опроса пользователя, а запись в decisions — только после его согласия; (3) `scripts/check-memory.sh` падает, если изменённые относительно HEAD файлы кода (`src/`, `e2e/`, `scripts/`, `package.json`, `playwright.config.js`) новее `frontend/tasks.md`.
- **Почему:** требование владельца проекта: память всегда актуальна, а выбор технологий остаётся за ним; проверка по времени изменения даёт механическую защиту от забытых обновлений.
- **Альтернативы:** обновлять память только по завершении задачи (риск устаревших данных между этапами); записывать решения автоматически (отвергнуто — решает владелец); проверка свежести через хук коммита (не выбрано: сложнее и срабатывает позже).
