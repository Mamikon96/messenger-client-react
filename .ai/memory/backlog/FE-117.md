# FE-117 (P2, харнес)

Из разбора прохода `qa-tester` по FE-40 (240 ходов, 21 млн токенов чтения кэша): у `mock-bff` нет управляемой имитации отказов, поэтому для кейсов про сбои сети, ретраи с backoff и лимиты агент каждый раз сам собирает мок через `page.route` и служебный эндпоинт и опрашивает его десятками `browser_evaluate`, ожидая реальное время. Эти кейсы уже детерминированно покрывает e2e из `npm run accept`. Варианты: (1) предпочтительный: в инструкции `qa-tester` и `acceptance.md` кейсы про отказы и тайминги не проходятся в браузере, в матрице `pass (e2e)` со ссылкой на e2e-тест с тегом `[UC-…]`, проверка `--require-qa` принимает такую отметку; (2) встроить управляемую имитацию отказов в `mock-bff` для e2e и QA. Выбор варианта — с пользователем; связано с FE-116 и FE-D47. Проверка: тесты `check-state.js` на новую отметку; критерий: `npm run accept` = 0.
