# mock-BFF (`mock-bff/server.js`)
> Проверено: 2026-10-21 @ aec3f34+dirty

Локальный Node-сервер (только `http`, без пакетов). Вход по паролю (`docs/client-integration.md` §1.3, §2.1–2.5): `POST /api/auth/register` (`201`, нормализация логина, `409 login_taken`, `400` с `details`, имя по кругу из 5 пар, частые пароли — короткий список) и `POST /api/auth/login` (`200`, `401 auth_failed`, `403 user_disabled` после верного пароля, `400`); пользователи в памяти (засеяны `alice`, `bob`, `admin`, `disabled`, пароль `correct-horse-1`); новая сессия уничтожает прежнюю из cookie запроса; cookie сессии без `Secure`, срок 400 дней, сессии в памяти; OAuth-маршрутов нет (FE-90). Запуск: `npm run mock-bff` (порт `MOCK_BFF_PORT`, по умолчанию 3334 — `DEFAULT_PORT`, его же берёт `playwright.config.js`; FE-81). Dev-сервер проксирует `/api` через `src/setupProxy.js` (`http-proxy-middleware` 2.x, devDependency) на `BACKEND_URL`, по умолчанию — реальный бэкенд `http://localhost:3333`. `playwright.config.js` поднимает mock-BFF и dev (3100) с `BACKEND_URL` на mock-BFF и задаёт `MOCK_BFF_URL`; для ручной работы с mock-BFF — `BACKEND_URL=http://localhost:3334 npm start`; тесты — `e2e/mock-bff.contract.spec.js` (прямо в mock-BFF), `e2e/mock-bff-proxy.spec.js` (через dev-сервер).

Данные и чаты (FE-44, §3.1 и §3.3): `GET /api/users?q=` — поиск по `name` (подстрока без регистра; q после trim 2..64 символа, иначе `400 validation_failed`; без q — весь справочник), без себя и отключённых, элементы `{id, name, avatarUrl}`; `POST /api/chats` — только `type: direct` (`201` + `ChatDto`, повтор с тем же `userId` — `200` с тем же чатом, `404 not_found` для неизвестного/отключённого, `400` для прочего тела; группы не поддержаны); чаты хранятся в памяти. `GET /api/chats` по-прежнему всегда `[]`, `GET /api/chats/:id` и сообщения — `404`: созданные чаты в них не попадают (сознательно, чтобы не менять существующие e2e).
