# Приёмка задач
Читать: когда задача реализована и нужно решить, можно ли её закрыть.

В «Сделано» — только при **обоих** условиях:
1. `npm run accept` → код 0 (`scripts/accept.sh`: `scripts/check-state.sh` — память, кейсы ↔ API ↔ код, тесты чекера + unit + e2e с матрицей «кейс → результат»).
2. Ревьюер `react-reviewer` вынес **APPROVE** по текущему коду (ревью — после зелёной приёмки).
3. Если задача меняет поведение приложения (`src/`, `mock-bff/`): агент `qa-tester` (FE-D17) прошёл в браузере все `active`-кейсы `docs/user-cases.md` и оставил свежий отчёт `.qa/report.md` с `Вердикт: PASS` (нет открытых BLOCKER/MAJOR). Проверка — `bash scripts/check-state.sh --require-qa`; её автоматически делает `scripts/git-task.sh commit`.

Порядок: реализация → `npm run accept` → проход `qa-tester` (если п. 3 применим; параллельно с ревью) → ревью → при `REJECT`/`APPROVE WITH FIXES` исправить все BLOCKER и MAJOR, повторить приёмку и **повторное** ревью → запись в «Сделано» с пометкой `ревью: react-reviewer APPROVE`.
Субагенты других агентов не запускают: ревью запускает основная сессия. Ревью не пройдено — задача остаётся «В работе» с пунктом «Осталось: ревью».
Изменения только конфигов/процесса/документации — ревью не требуется (отметить это в записи).
После записи в «Сделано» (и обновления памяти) — автоматический коммит на ветке задачи по `.ai/rules/git-flow.md`. Без выполненной приёмки коммит не делается.

## Адрес бэкенда при приёмке
- Реальный бэкенд (`messenger-server`) доступен на порту **3333**, если в переменных окружения адрес не задан (`BACKEND_URL` не установлен): `src/setupProxy.js` проксирует `/api` и `/mock-provider` на `http://localhost:3333`.
- Mock-BFF по умолчанию тоже слушает порт 3333 (`MOCK_BFF_PORT`), поэтому реальный бэкенд и `npm run accept` одновременно не работают: перед приёмкой остановить реальный бэкенд (занятый порт даёт ошибку запуска, а не молчаливый прогон на нём).
- Playwright e2e из `npm run accept` идут на mock-BFF (`playwright.config.js`: `BACKEND_URL` задаётся для dev-сервера e2e).
- Проход `qa-tester` и ручная проверка с реальным бэкендом: если `BACKEND_URL` не задан, использовать `http://localhost:3333`.

## Цикл тестировщика (qa-tester)
- Запускает основная сессия после зелёной приёмки (субагенты агентов не запускают). Агент сам поднимает приложение, проходит кейсы руками (Playwright MCP + Chrome DevTools MCP), код не правит; результат — `.qa/report.md` (вне git).
- `Вердикт: FAIL` → отчёт передаётся `react-engineer` на исправление **всех** BLOCKER и MAJOR → `npm run accept` → **повторный** полный проход `qa-tester`. Старый отчёт устаревает сам: в нём хэш кода и хэш кейсов (`node scripts/check-state.js --tree-hash`).
- Кейс нельзя пройти (`blocked`) или он неясен — вопрос пользователю, не допущение. Playwright e2e из приёмки не убирается: агент его дополняет (FE-D17).
- Изменения только конфигов/процесса/документации — проход тестировщика не требуется (отметить в записи).
