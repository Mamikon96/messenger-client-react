# Протокол памяти
Читать: перед началом работы над задачей разработки (шаг «Старт») и перед ответом пользователю после любых изменений (шаг «После правок»).
Источник: FE-D27, FE-D41; исполняют `scripts/check-memory.sh` и hook `Stop`. Пересмотреть, когда меняется формат памяти или hooks.
Описание файлов памяти и их форматов — `.ai/memory/README.md`.

## Старт (читать минимум)
- Первым шагом — `bash scripts/git-task.sh start …`: проверка состояния (репозиторий, задача в `tasks.md`, чистота дерева, актуальность базы, `check-memory.sh`), затем переключение на ветку задачи (`.ai/rules/git-flow.md`, «Автоматический цикл»).
- Сводку («В работе», последняя приёмка, фокус) в начале сессии печатает hook `SessionStart` (`scripts/session-brief.sh`); если она в контексте — для продолжения задачи `tasks.md` целиком не перечитывать. Целиком `.ai/memory/tasks.md` — когда берёшь задачу из бэклога или заводишь новую. Задача из бэклога → сразу в «В работе» с контрактом (`.ai/rules/task-contract.md`, проверяет `scripts/check-contract.sh`); тесты и код — только после согласования открытых вопросов.
- Остальное — только по необходимости (таблица «когда читать» в `.ai/memory/README.md`): `state.md` — баг/регрессия/известные проблемы; `architecture.md` — новые модули, правка структуры; `decisions.md` — архитектурный выбор или новая технология (искать по заголовкам, не читать целиком).
- Факты из памяти перепроверять по коду: расхождение = память неверна, исправить.

## После правок (до ответа пользователю)
После ЛЮБЫХ изменений (код, тесты, конфиги):
1. `tasks.md`: промежуточный прогресс → «Осталось»; новая найденная работа → «Бэклог»; правка вне задач → отдельная запись («В работе» или «Сделано»).
2. `state.md` — по сверке с кодом, каждая проблема с путём к файлу; `architecture.md` — если изменилась структура.
3. Штамп `> Проверено: ГГГГ-ММ-ДД @ <sha>[+dirty]` (дата — `date +%F`, sha — `git rev-parse --short HEAD`).
4. `bash scripts/check-memory.sh` (падает, если код изменён позже `tasks.md`). Hook `Stop` (`scripts/hooks/stop-memory-check.sh`) запускает его сам перед концом ответа и возвращает агента к работе при ошибке.
- «Сделано» — архив `.ai/memory/done.md` (раздел в `tasks.md` не ведётся; читать только за историей): запись с датой добавляется в конец только при выполнении `acceptance.md`, задача удаляется из `tasks.md`. Запись — одна строка `- ГГГГ-ММ-ДД — FE-NN: … · Кейсы: <UC-… из контракта> | нет · …`: поле «Кейсы:» обязательно — по нему `--require-qa` при `git-task.sh commit` восстанавливает объём QA (FE-D35).
- Запись в `decisions.md` — сразу после выбора пользователя, не раньше (`tech-approval.md`); без выбора не писать.
- Не дублировать в памяти то, что очевидно из кода или git.

## Итог
Финальный отчёт — по шаблону `.ai/rules/report-format.md`, строится из обновлённых файлов памяти.

## Сессия и контекст (FE-D41)
- Одна задача — одна сессия; между задачами `/clear`. Контекст сессии дорожает с каждым ходом, поэтому порог абсолютный и зависит от модели основной сессии: Sonnet/Haiku — 90K, Opus и прочие — 150K токенов (не доля окна). Hook `Stop` (`scripts/hooks/context-guard.sh`) возвращает агента при достижении порога: сохранить «Осталось» в `tasks.md`, штамп, `check-memory.sh` = 0 и закрыть сессию. В субагентах тот же порог проверяет hook `PostToolUse` (по `agent_id`): после инструмента агент получает указание сохранить состояние и завершиться отчётом «сделано / осталось».
- Код задачи пишет `react-engineer`; основная сессия ведёт контракт, гейты и git.
- Бэклог — индекс: строка ≤200 символов, подробности — .ai/memory/backlog/FE-NN.md (открывать, когда задачу берут в работу). Заменённые решения лежат в `.ai/memory/decisions-archive.md` — искать там только историю.
