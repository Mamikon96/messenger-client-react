# QA: стенд и известные особенности
Читать: `qa-tester` — перед запуском приложения (шаг «Запуск») и при первой трудности с входом, навигацией или кликом.
Источник: прошлые проходы QA (`.qa/runs/`), FE-44, FE-D43, FE-D54. Пересмотреть, когда меняется форма входа или mock-BFF (в т.ч. закрыт FE-159).

## Стенд
Факты о стенде, на которых прошлые проходы теряли время. Это не подсказки к кейсам: что проверять, по-прежнему определяет только набор user-кейсов.
- **Вход.** Форма «Логин» + «Пароль», кнопка «Войти» (вкладка «Регистрация» — «Зарегистрироваться»). Засеянные пользователи mock-BFF: `alice`, `bob`, `admin`, `disabled`, пароль `correct-horse-1`; для регистрации нужен свободный логин. Вход без перезагрузки страницы; признак мессенджера — поле «Поиск людей» над списком чатов.
- **Навигация.** После перехода (`goto`, клик по входу, `reload`) дождись результата (`browser_wait_for` по тексту, в коде — `page.waitForURL`/`waitForLoadState`) и только потом читай страницу. Иначе «Execution context was destroyed» / «page is navigating».
- **Клики.** `browser_click` принимает ref из последнего snapshot, а не текстовый или CSS-селектор. Ответ клика, навигации и `browser_wait_for` содержит snapshot страницы либо (в новых версиях Playwright MCP) только ссылку на файл `.playwright-mcp/page-*.yml`; если нужны свежие ref, вызови `browser_snapshot` (он возвращает snapshot в ответе), а не читай этот файл через Bash.
- **Ограничение mock-BFF (FE-159).** Mock отдаёт поиск людей и `POST /api/chats`, но не отдаёт чаты и историю: `GET /api/chats` всегда `[]`, `GET /api/chats/:id` и `/messages` и `POST .../messages` — 404. У чата, созданного из поиска, сразу «Не удалось загрузить сообщения», после перезагрузки чат пропадает. Это известное ограничение стенда, не дефект клиента: кейсы про чаты и сообщения проходи с подменой ответов (`page.route` / `routeWebSocket`) по контракту `docs/client-integration.md`, отмечай это в отчёте.
- **`browser_run_code_unsafe`** — один короткий сценарий на вызов, с ожиданием после каждой навигации; длинный скрипт на несколько кейсов падает целиком и требует повтора.
- **Остановка серверов.** Только `kill <PID>` процесса, слушающего порт: `ss -ltnp 'sport = :3100'` (и `:3334`) → `pid=…`. `pkill -f <шаблон>` не использовать: шаблон есть в командной строке самого Bash, и `pkill` убивает собственный шелл (exit 144).
